# `dev-algo` 代码审查与完善清单（2026-08-25 至 2026-08-31）

## 1. 结论

本轮改动的主线清楚，且在目标六旋翼 SITL 场景中已经表现出实际收益：恒速圆弧把 U 转掉速压到约 2%，单电机停转后的伪逆重分配能在 4 m/s 风中维持姿态，围栏和物理模型的测试工具也比原来完整得多。

但当前版本还不适合把新增能力直接当作“通用、闭环安全功能”发布。合入真机前建议至少先关闭以下两个高风险缺口：

1. 姿态模式围栏所谓“硬限”在飞手松杆时不能主动刹车，高速滑行仍可能越界；
2. 电机失效分配器在退化矩阵求逆失败时仍返回成功，首轮失败可把所有有效电机输出成零。

此外，圆弧控制的模式退出清理、入弧条件、围栏/避障/地形约束、MAVLink 目标回传，以及电机分配的 yaw 参数语义和抗积分饱和反馈，都需要在真机放飞前补齐。

## 4. 必须优先修复的问题

### R-01（P0）姿态模式围栏在松杆时无法主动刹车

位置：`libraries/AC_Avoidance/AC_Avoid.cpp:549-590`

`adjust_velocity_fence()` 可以算出反向制动加速度，但随后输出倾角幅值被限制为“不超过飞手输入幅值”。飞手松杆时输入幅值为零，因此任何制动倾角都会被再次压成零。高速接近围栏、飞手在边界前松杆时，飞机只能靠自然阻力减速，不能兑现“硬限、飞不出围栏”的承诺。

同一段代码只限制输出向量的模长，并没有限制方向；在 `BEHAVIOR_SLIDE` 等路径中，输出仍可能旋转到飞手没有请求的方向。因此“不会自己做动作”的注释与真实数学约束也不一致。

建议：

1. 明确安全契约：硬围栏应允许系统施加“只朝安全区、且有独立上限”的主动制动；
2. 分解法向/切向分量，只移除向外分量，并按当前速度和停止距离产生有限的向内制动，不用飞手杆量作为制动上限；
3. 位置或速度估计不可用时，不应静默放行，可触发可配置的 LOITER/BRAKE/RTL 降级；
4. 增加“高速接近后松杆”“已经侵入 margin”“零杆漂移”“多边形顶点/边心”验收场景。

验收：在最大允许水平速度、零杆、最不利顺风下，圆形和多边形围栏均不得越界；所有自动制动指令的法向分量只能指向安全区。

### R-02（P0）分配矩阵奇异时仍返回成功，可能输出全零

位置：`libraries/AP_Motors/AP_MotorsMatrix.cpp:678-683,763-810`

分配器先把 `thrust[]` 初始化为零。`mat_inverse()` 失败时只是 `break`，循环结束后仍复制当前数组并返回 `true`。如果第一次求逆就失败，调用方会把所有仍启用的电机输出改成零；如果夹紧后的后续求逆失败，则返回的也是未证明满足需求的半成品。

`n >= rows` 只说明电机数不少于约束数，不代表矩阵满秩或条件数可接受。脚本构型、非对称构型、停对侧电机和多电机夹紧都可能触发退化。

建议：

1. 首轮求逆失败必须返回 `false`，调用方回退到明确的安全策略；
2. 每轮保留“最后一个已验证可行解”，后续退化时只能回退到该解，不能返回半成品；
3. 检查秩、条件数和最终残差，而不只检查电机数量；
4. 活跃集每次只固定最严重的违反项再重算，避免一次夹紧多个电机造成不必要的秩丢失；
5. 在参数启用和预解锁阶段验证当前 frame/失效位置是否支持退化分配。

验收：对所有支持的 frame、每个单电机失效位置和上下限夹紧组合做穷举；任何求解失败都不得产生比原固定混控更危险的输出，更不得把有效电机全部置零。

## 5. 高优先级和工程完善项

### R-03（P1）`MOT_FAIL_YAW` 与默认重分配模式的语义不一致

位置：`AP_MotorsMatrix.cpp:420-425,735-793,830-899`

默认 `MOT_FAIL_ALLOC=1` 时，调用固定为 `allocate_redistributed(demand, false, ...)`，yaw 目标不进入三行求解。`MOT_FAIL_YAW` 虽会缩放实时 `_yaw_factor`，但不会成为重分配器要追踪的 yaw 需求；它最多通过求解前的旧混控计算产生间接影响，不能实现参数描述中的“保留某一比例 yaw 权限”。

建议把“yaw 目标跟踪权重”和“零空间寄生 yaw 抑制”定义成两个明确、连续的代价项。若暂不支持 yaw 目标，`MOT_FAIL_ALLOC=1` 时应拒绝非零 `MOT_FAIL_YAW`，避免参数看似生效。

### R-04（P1）重分配后的饱和没有反馈给 PID 抗积分饱和

位置：`AP_MotorsMatrix.cpp:290-405,409-448,782-810`

`limit.roll/pitch/yaw/throttle_*` 来自重分配前的固定混控、缩放和限幅；伪逆分配器随后重新夹紧电机，却没有根据实际可达广义力更新 limit 标志。速率 PID 因而可能在不可达方向继续积分，或被错误地禁止积分。

建议计算 `achieved = B * thrust_out`，与输入 demand 比较后按轴和方向设置饱和反馈；同时记录 demand、achieved、残差、活跃约束和条件数，才能用日志解释失效后的控制行为。

### R-05（P1）圆弧临时限幅缺少统一的退出清理

位置：`ArduCopter/mode_auto.cpp:597-603,625-651,103-113`；`mode_guided.cpp:302-332`

圆弧开始会提高 `AC_PosControl` 的速度、加速度和修正限幅，但目前只在“正常跑到终点”时恢复。AUTO `exit()` 没有恢复或停止 `auto_arc_nav`，GUIDED 也没有圆弧专用 exit；切模式、解锁状态变化、failsafe、任务暂停/跳转/重传和新 Guided 指令都可能绕过正常完成路径。

建议集中实现 `arc_stop_and_restore()`，保存进入前的真实限幅而不是假定都等于 WPNAV 默认值，并从正常完成、模式退出、任务中止、failsafe、disarm 和新目标覆盖等所有路径调用。增加中途切换和任务变更测试。

### R-06（P1）入弧条件不足，AUTO 可从悬停或反向速度直接启动恒速参考

位置：`mode_auto.cpp:546-611`；`mode_guided.cpp:223-251`；`AC_ArcNav.cpp:208-225`

GUIDED 只检查速度大小达到目标的 70%，不检查速度方向是否与入口切线一致；AUTO 连速度大小也不检查。LOITER_TURNS 作为首个导航项、前项为悬停/延时/起飞，或飞机正沿反方向运动时，参考仍会立即按工作速度前进。

`set_arc()` 也只要求当前位置离圆心超过 0.1 m，不校验实际径向距离与命令半径是否一致，因此命令圆心和实际飞行几何可能不一致。

建议同时检查：入口速度大小、速度与切线的点积、径向误差、预计位置误差和 yaw 状态。条件不满足时先走显式的接入轨迹，或保持标准 LOITER_TURNS 行为，不应直接启动恒速弧。

### R-07（P1）AUTO 前视与圆弧可行性判定不是原子操作

位置：`mode_auto.cpp:1772-1849,1915-1952`

前一航段只要看到 `turns <= 0.5`，就固定按 10 m 切线前视处理；真正的倾角、yaw 速率和圆弧可行性要等进入下一任务项后才判断。若 `arc_start()` 随后拒绝，前一航段已经改变了减速和目标几何，回退的标准 circle 不再拥有标准入口条件。

固定 10 m 也没有随速度、半径、jerk、螺线长度和 WPNAV 到达半径变化。

建议在规划前视时完成同一套可行性检查，或把“前视承诺 + 圆弧启动”放入同一状态机；前视距离由实际过渡长度计算，失败时完整回退标准任务语义。

### R-08（P1）圆弧直驱位置控制器，绕过围栏、避障和地形约束

位置：`AC_ArcNav.cpp:335-408`；`mode_guided.cpp:214-310`；`mode_auto.cpp:546-682`

圆弧每周期直接写入 `AC_PosControl`，没有经过 `AC_WPNav_OA`、BendyRuler、`AC_Avoid::adjust_velocity()` 或路径围栏检查。GUIDED 接口甚至只检查圆心非零，没有验证整条弧是否位于围栏内。AUTO/GUIDED 仍会在越界后触发 `FENCE_ACTION`，但那不是主动路径约束。

圆弧还把高度固定为进入时的 `pos_desired_U`，忽略 LOITER_TURNS 命令高度和 terrain-relative 语义。坡地作业时，这会与普通 WPNAV 的地形跟随行为不同。

建议在接受前对整条参数曲线做围栏/禁飞区采样和地形裕度检查，运行时继续监测；需要 OA 时拒绝恒速弧或切换到受约束的局部规划器。明确支持命令高度和 terrain frame，不能静默保持旧高度。

### R-09（P1）GUIDED 圆弧回传的是陈旧目标

位置：`GCS_MAVLink_Copter.cpp:169-176`；`mode_guided.cpp:1281-1293`；`AC_ArcNav.cpp:399-402`

`POSITION_TARGET_LOCAL_NED` 把 Arc 当作 PosVelAccel 回传，但 getter 返回的是 `guided_pos/vel/accel_target_*`。圆弧只更新 `AC_PosControl`，没有更新这些静态变量，因此地面站、伴随计算机和日志看到的是进入圆弧前的旧目标。

建议 Arc 分支直接读取 `pos_control` 的 desired 三元组，或由 ArcNav 每周期同步 Guided 公共目标；同时补 `wp_distance`、bearing 和 crosstrack 的一致语义。

### R-10（P1）偏航权限代码为空，且标准任务语义被隐式改写

位置：`mode_guided.cpp:315-320,369-380`；`mode_auto.cpp:15-29,1937-1946`

GUIDED `arc_run()` 中“让飞手保留 yaw 权限”的 if 块为空，后续仍无条件命令切线航向。`GUID_OPTIONS` 的 pilot-yaw 语义与实际行为不一致。

AUTO 还把所有 `LOITER_TURNS <= 0.5` 自动解释为协调圆弧，改变了已有任务的停驻、航向和高度行为，并忽略 MAV_CMD 的 param4 yaw 语义。建议新增显式参数/任务标志，默认保持旧行为；更稳妥的是使用自定义命令或脚本任务项，而不是按 turn 数隐式劫持标准命令。

### R-11（P1）集中回归会吞错误，并可能复用旧结果造成假通过

位置：`Tools/eft_issue_repro/regression.py:196-218`

`subprocess.run()` 没有检查返回码，stdout/stderr 全部丢弃；随后按固定 variant 全局 glob，并读取字典序最后一个 `result.json`。当前运行若失败，但目录里存在旧的同名 variant，脚本会用旧结果判定本次通过。

本次在受限环境首次运行时，所有子进程因 localhost socket 权限失败，报告只显示“未产生结果”，没有暴露真实异常，已经实际触发了前半个问题。

建议每个 case 使用本次 regression 目录下的唯一 `--output`，检查返回码，只读取明确的预期结果路径；失败时保留 stdout/stderr、SITL 日志和命令行。报告应写入 commit、固件 hash、参数链和模型 hash，禁止跨构建复用。

### R-12（P2）速度前馈的辨识 lane 和在线可观测性不完整

位置：`Tools/eft_issue_repro/fit_vel_ff.py:45-90`；`AC_AttitudeControl_Multi.h:94-102`

拟合工具固定读取 XKF/NKF core 0，而当前 EFT 默认启用两条 EKF3 lane。发生 primary lane 切换时，`ATT.Yaw`、飞控在线使用的速度和离线 core 0 可能不属于同一估计器，拟合增益会被污染。

头文件虽暴露 `get_vel_ff()` 和输入 getter，并称用于日志，但当前没有任何调用者，实际日志不能直接确认前馈输入、限幅和输出。

建议按日志中的活动 primary core 逐段选取状态，lane 切换附近剔除；新增 VFF 日志消息，记录地速/风修正后空速、滤波输入、未限幅输出和最终输出。真机标定应做留出航段交叉验证，不能只用同一架次拟合并验收。

### R-13（P2）多电机低转速告警没有节流

位置：`AP_MotorsMatrix.cpp:643-655`

多个电机同时低于门限时，每个 mixer 周期都会发送 STATUSTEXT。遥测映射错误或总线异常可导致持续高频告警，占用队列并淹没更重要信息。建议做状态沿触发和 1~5 s 限频，恢复时再发一次恢复消息。

### R-14（P2）手工失效参数是持久化飞行陷阱

位置：`AP_MotorsMulticopter.cpp:234-290`；`AP_MotorsMatrix.cpp:220-229`

`MOT_FAIL_IDX` 是持久参数，非零时会不可逆地从本次启动的 mixer 中移除电机；没有预解锁提示要求测试完成后清零，也没有限制到 SITL/专用测试模式。建议默认只允许 disarmed + 显式 test option，并在非零时阻止正常解锁或持续给出明确预解锁失败原因。

### R-15（P2）SITL 地效把机体气动阻力一起放大

位置：`libraries/SITL/SIM_Frame.cpp:718-764`

代码先执行 `thrust -= drag_bf`，随后用 `thrust *= 1 + ground_effect_state`。因此地效增益不仅放大旋翼升力，也会放大 x/y/z 机体阻力。建议单独保存 rotor thrust，对其施加地效后再与 drag 合成；若地效对力矩也有影响，应单独建模，而不是只改合力。

### R-16（P2）文档和注释已经落后于实现

需要同步的明显位置：

- `Tools/eft_issue_repro/README.md` 仍只称支持两个场景，并列出已经被替换的旧地效字段；
- `reproduce.py:846-855` 仍称 ALT_HOLD/STABILIZE 原理上无法主动围控；
- `AC_ArcNav.h:118-119` 把正 sweep 写成“俯视逆时针”，但 NE 航向角增大实际是顺时针；
- Guided 接口注释把负 radius 写成顺时针，而实际行为和 MAVLink XML都是“正值顺时针、负值逆时针”。

建议把方向约定统一写成“NE/NED 航向角正方向”和 MAVLink param3 规范，并给 CW/CCW 各加一个自动化测试，避免只改注释又掩盖真实符号错误。

## 7. 建议实施顺序

1. 先修 `R-01`、`R-02`、`R-11`，确保安全边界和测试结论可信；
2. 修 `R-03`、`R-04`，给失效分配器补参数契约、残差和抗饱和反馈；
3. 用统一的圆弧生命周期状态机处理 `R-05` 至 `R-10`；
4. 补齐跨模式、跨 frame、CW/CCW、围栏、地形、任务中止和估计器切 lane 测试；
5. 最后处理日志、告警限频、SITL 物理隔离和文档同步。

在上述 P0/P1 项关闭前，建议：

- 真机保持 `MOT_FAIL_RPM=0`，只在系留或专用安全试验中启用自动摘除；
- 不把 `LOITER_TURNS <= 0.5` 的新语义用于生产任务；
- 姿态模式围栏仍把 `FENCE_ACTION` 当最终保护，不宣称零杆高速状态下可以物理阻止越界；
- 圆弧试飞只使用已验证的六旋翼、已知入口速度/方向、平坦地形和足够大的无障碍区域。
