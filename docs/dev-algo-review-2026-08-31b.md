## 4. 新发现

### N-01（P0，唯一遗留）分配器仍会提交未验证的半成品

位置：`libraries/AP_Motors/AP_MotorsMatrix.cpp:882`、`:888-899`

`allocate_redistributed()` 是一个**活跃集迭代**：每轮解一次最小范数问题，把越界的电机夹到 `[0,1]` 并冻结，带着剩余需求重解。关键的几行：

```cpp
882:        have_solution = true;
883:        if (!clamped_any) {
884:            break;
885:        }
886:    }                       // 下一轮
887:
888:    if (!have_solution) {
893:        return false;       // 只挡住「一轮都没成功过」
894:    }
895:
896:    for (uint8_t k = 0; k < n; k++) {
897:        thrust_out[idx[k]] = constrain_float(thrust[k], 0.0f, 1.0f);
898:    }
899:    return true;
```

`have_solution` 在**夹紧发生的那一轮也会置位**。而 `clamped_any == true` 的含义正是"这一轮的解不可用，需要下一轮重新分配"。于是：

- 第 1 轮：解成功、残差通过，两台电机越界被夹紧冻结。`have_solution = true`，`clamped_any = true`，继续。
- 第 2 轮：`mat_inverse()` 失败（或 NaN、或残差超限）→ `break`。
- 第 888 行判断不成立 → 直接提交 `thrust[]` 并 `return true`。

提交的 `thrust[]` 里被夹电机是夹紧值（正确），**自由电机携带的是第 1 轮的值**——那组值是在"被夹电机输出其未夹紧值"的前提下解出来的。夹紧改变了剩余需求，第 2 轮本应重新分配但它失败了。因此 `B·t ≠ demand`，力矩不平衡，而调用方（`:425`）拿到 `true` 就把它直接写进 `_thrust_rpyt_out[]`。叠加尚未关闭的 `R-04`（`limit.*` 仍来自前向混控），速率 PID 连饱和反馈都拿不到。

**可达性已数值验证**（DJI_X 六旋翼几何，4 号电机失效，`rows = 3`）：

```
pass 1: 自由 5 台  det(B Bᵀ) = 27    可逆
pass 2: 自由 4 台  det(B Bᵀ) = 12    可逆
pass 3: 自由 3 台  det(B Bᵀ) =  3    可逆
pass 4: 自由 2 台  det(B Bᵀ) =  0    奇异 → mat_inverse 失败 → break
```

`B` 是 3×2，`B Bᵀ` 秩至多 2，3×3 行列式必然为 0——恒等式，不是数值巧合。每轮至少夹紧一台、循环上限 `pass <= n` 允许走到底，所以**只要在饱和工况下连续夹紧三台就必定命中**。

这正是原审查 `R-02` 建议清单第 2 条要求的："每轮保留「最后一个已验证可行解」，后续退化时只能回退到该解，不能返回半成品。" `f4f8550de2` 实现了第 1 条（首轮失败返回 `false`）和第 3 条（秩/条件数检验），跳过了第 2 条。

**建议**：把"已验证可行"收紧为**这一轮解出的推力全部落在 `[0,1]` 内**，即

```cpp
        if (!clamped_any) {
            have_solution = true;         // 只在完全可行时置位
            memcpy(thrust_ok, thrust, sizeof(thrust_ok));
            break;
        }
```

后续任何一轮退化时回退到 `thrust_ok`；若从未出现过完全可行的一轮，返回 `false` 退回前向混控。改动是移动一行加一次数组拷贝。

同时建议补一组表驱动单元测试，穷举 frame × 失效位置 × 夹紧组合，断言"返回 `true` 时 `B·t` 与 `demand` 的残差在门限内"。这是唯一能挡住同类回归的手段，也是 `R-02` 建议清单第 4 条的落点——`R-11` 修好之后，这类断言才有地方可靠地跑。

### N-02（P1，潜伏）气流力矩前馈绕过速率 PID，落地时不受抑制

位置：`libraries/AC_AttitudeControl/AC_AttitudeControl_Multi.cpp:493,496`

```cpp
_motors.set_roll (get_rate_roll_pid ().update_all(...) + _actuator_sysid.x + _vel_ff.x);
_motors.set_pitch(get_rate_pitch_pid().update_all(...) + _actuator_sysid.y + _vel_ff.y);
```

`_vel_ff` 加在 PID **之后**，直接进混控。两个后果：

1. **`landed_gain_reduction()` 对它无效。** ArduCopter 在 `update_flight_mode()` 里调 `attitude_control->landed_gain_reduction(copter.ap.land_complete)`，落地后压低增益以避免与地面对抗。该机制作用于 PID 增益，而 `_vel_ff` 在 PID 之外，完全不受影响——这是全机唯一的"别跟地面较劲"机制，新增的力矩项恰好在它管辖范围外。
2. **不参与 PID 的饱和处理。** `update_all(..., _motors.limit.roll, ...)` 让 PID 知道自己饱和了，但 `+ _vel_ff.x` 发生在之后，合成量可以越过限幅逻辑记录的范围。

`update_velocity_feedforward()` 由 `rate_controller_run_dt()` 每个速率周期无条件调用，**没有 armed / spool state / land_complete 门控**。落地后若 EKF 报出非零水平速度（GPS 噪声、被搬动、大风中机体轻微移动），前馈就会注入一个恒定滚转/俯仰力矩，上限 `ATC_VFF_MAX`（默认 0.15 归一化力矩）。在斜坡或风中 spool-up 阶段这是实打实的翻机风险方向。

**现状缓解**：`ATC_VFF_RLL`/`ATC_VFF_PIT` 默认均为 0，前馈整体关闭，**今天的固件不受影响**。但 P02 的整定一旦落地，这两个参数就会被设成非零——修复应赶在那个时点之前。

**建议**：在 `update_velocity_feedforward()` 开头与既有的"速度估计不可用则清零并 reset 滤波器"分支合并一个门控：未解锁、spool 状态非 `THROTTLE_UNLIMITED`、或 `land_complete` 时同样清零并 return。若希望前馈随落地增益一起衰减而非硬切，可复用 `landed_gain_reduction()` 已算出的比例因子。

### N-05（P1）`STABILIZE-2m/s风` 用例每次必失败，且失败与围栏无关

`STABILIZE` 是纯手动油门且无高度保持，脚手架为了顶到有效高度把油门杆压在 `--fence-throttle 1650`（高于悬停）。切到 `LAND` 后这个 RC override 的状态没有被处理，飞机在 120 s 内没有落地上锁。`DRIFT` 用同样的 1650 却通过，差别在于 `DRIFT` 有 `get_throttle_assist()` 的垂向阻尼而 `STABILIZE` 完全没有——但我没有进一步隔离到确切成因，只确认了现象可稳定复现。

**建议**：收尾前先把油门杆降到最低再切 `LAND`，或对手动油门模式改用显式的降高流程；在修好之前，宁可把这条用例暂时移出 `SUITE` 并在注释里写明原因，也不要留一个已知必失败的条目在里面。

### N-03（P2）`AC_ArcNav` 的高度是进入时快照

位置：`libraries/AC_WPNav/AC_ArcNav.cpp:219,399`

`_alt_u_m` 在 `set_arc()` 里从 `pos_control->get_pos_desired_U_m()` 取一次，之后每周期原样写回位置控制器。圆弧全程锁定进入瞬间的 EKF 原点系高度，既不理会 `LOITER_TURNS` 命令自带的高度，也不做地形跟随。坡地作业时同一条航线上普通 WPNAV 段跟地形、圆弧段不跟，接缝处会有高度阶跃。

属审查 `R-08` 的一部分，本轮读码确认无误，记在此处以便与 `R-08` 其余部分（绕过围栏/避障）一起处理。

### 一处不是缺陷但值得写明的地方

`allocate_redistributed()` 里的 `rem[0] *= (float)n;`（`:730`）用的是**存活电机数**，不是失效前的电机数。六旋翼失效一台后前馈给出的总升力是 `5d`，而维持原升力需要 `6d`——短 1/6。这不是 bug：`d` 就是高度控制器的输出，闭环会把它抬到 `6d/5`，代价只是失效瞬间的一点掉高（实测 0.04 m）。写在这里是因为代码注释解释了"为什么要乘 n"，但没说清"乘的是哪个 n"，容易被后人"修正"成失效前的数量而引入一个真正的前馈过冲。
